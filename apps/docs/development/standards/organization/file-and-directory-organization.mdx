## Repository Structure Overview

The repository holds a Go module and a pnpm workspace side by side. Everything runs from the root: the `Makefile` orchestrates both, and the TypeScript side runs through Vite+ (`vp`).

| Path | What it is |
| --- | --- |
| `server/` | The Go module `github.com/yldm-tech/forma/server`: one binary, `forma`, whose subcommands are the processes. |
| `web/` | The admin single-page app, and the public survey page bundle the server fills for `/s`, `/c` and `/p`. |
| `packages/` | Shared TypeScript: the survey runtime, the SDK, UI components, types and i18n helpers. |
| `apps/storybook/` | Storybook for `packages/survey-ui`. |
| `e2e/`, `playwright.config.ts` | The Playwright browser suite. |
| `scripts/` | Repository checks and CI helpers; a workspace of its own so its tests run. |
| `authzed/` | The SpiceDB schema (`schema.zed`) and its assertion suite. |
| `docs/` | Product and API documentation (Mintlify); `docs/api-v3-reference` is the source of the v3 OpenAPI contract. |
| `Dockerfile`, `docker/`, `charts/forma/` | The production image, the production compose stack and the Helm chart. |
| `docker-compose.dev.yml` | The local dependencies: PostgreSQL, Valkey, SpiceDB, RustFS and Mailpit. |

## The Server

```
server/
├── cmd/forma/          # main: the subcommands (start, serve, worker, migrate, seed, authz, ...)
├── migrations/         # goose SQL migrations, embedded into the binary
└── internal/
    ├── app/            # composition root: wire.go, the generated wire_gen.go, the router
    ├── platform/       # cross-cutting infrastructure
    │   ├── config/     # every environment variable, read once at startup
    │   ├── database/   # connection, migrations, the migration lock
    │   ├── httpapi/    # /api/app conventions: errors, binding, the CSRF check, the caller
    │   ├── jobs/       # the River job queue
    │   ├── mailer/     # templates and SMTP
    │   ├── ratelimit/  # Valkey-backed limits with forma2's rules
    │   ├── pgtest/     # a fresh migrated database per test
    │   └── ...
    ├── authz/          # SpiceDB: the authorizer, the projection and its outbox
    ├── seed/           # forma seed: development and contract-test data
    ├── survey/         # one package per feature: handler.go, service.go, repository.go
    ├── response/
    ├── workflow/
    └── ...
```

Each feature package is layered **handler → service → repository**: the handler binds and validates input and renders the answer, the service authorizes once and holds the business rules, and the repository talks to the database. A feature's routes are registered by its handler's `Register` (or `RegisterV3` for `/api/v3`), mounted by `NewRouter` in `internal/app/router.go`.

## The Admin UI

```
web/
├── locales/            # i18next catalogues (en-US, ja-JP, zh-Hans-CN, zh-Hant-TW)
├── index.html          # the SPA entry
├── survey.html         # the public survey page entry
└── src/
    ├── routes/         # TanStack Router file-based routes; routeTree.gen.ts is generated and committed
    ├── features/       # one directory per feature: its components, hooks and logic
    ├── components/     # shared UI components
    ├── lib/            # the API client, query factories, shared helpers
    └── survey-page/    # the public survey page bundle
```

Route files stay thin: they declare the route, its loader (which prefetches through the same `queryOptions` factories the components use) and the page component from `features/`.

## Packages

### packages/surveys/

- The Preact survey runtime, shipped as `/js/surveys.umd.cjs`.
- Renders surveys on customer sites (through the SDK) and on the public survey pages.

### packages/js-core/

- The customer-site SDK, shipped as `/js/forma.umd.cjs`.
- Tracks actions, decides which survey to show, and loads the runtime.

### packages/survey-ui/

- Shared survey UI components, which ship their own CSS (`@forma/survey-ui/styles`), since Tailwind does not scan `node_modules`.

### packages/types/

- zod schemas and TypeScript types for the survey document and other shared shapes.
- `json-schema-registry.ts` lists the schemas exported to `server/internal/jsonschema/schemas/`, which the Go server validates JSON documents against.

### packages/i18n-utils/

- Language helpers, and the translation scanner (`pnpm scan-translations`).

### packages/config-typescript/, packages/vite-plugins/

- Shared `tsconfig` bases and build plugins (the one that copies the SDK bundles into `web/public/js/`).

## Adding New Code

### A new server feature

1. Create `server/internal/<feature>/` with its handler, service and repository.
2. Add the constructors to a provider set in `internal/app/wire.go`, run `make generate`, and mount the handler in `NewRouter`.
3. A schema change is a new numbered migration in `server/migrations/`; a table that carries authorization data also needs its projection trigger.
4. A new `/api/v3` operation is documented in `docs/api-v3-reference` first; the route parity test fails until both sides agree.

### A new screen

1. Add a route file under `web/src/routes/` and the feature's components under `web/src/features/<feature>/`.
2. Server state goes through TanStack Query with a `queryOptions` factory in `web/src/lib/queries/`, and calls go through `api` in `web/src/lib/api.ts`.
3. User-facing text goes into `web/locales/*.json` for every locale; the translation scan fails on a key one locale lacks.

## Testing Organization

- Go tests are `*_test.go` files next to the code they test.
- TypeScript tests are `*.test.ts(x)` files next to the code they test, inside a workspace with a `test` script.
- Browser specs are `e2e/*.spec.ts`.
- Test fixtures a Go test reads live in a `testdata/` directory beside it.

See [Testing Methodology](/development/standards/qa/testing-methodology).

## Configuration Files

### Root level

- `package.json`, `pnpm-workspace.yaml`: the workspace, its scripts and the catalog that pins every dependency shared by two or more workspaces.
- `vite.config.ts`: the only formatting and lint configuration.
- `Makefile`: the entry points for both halves (`make deps-up`, `make migrate`, `make seed`, `make dev-server`, `make dev-web`, `make build`, `make check`).
- `.env.example`: every variable the server reads, with what it does.
- `playwright.config.ts`: the browser suite.

### Package level

- `package.json` with the package's own scripts and dependencies (shared ones as `catalog:`).
- `vite.config.ts` (or `.mts`) with the package's build and test settings.
- `tsconfig.json` extending a base from `packages/config-typescript`.

### Server

- `server/go.mod`: the Go version and dependencies.
- `server/.golangci.yml`: the linters.
- `server/.squawk.toml`: the migration linter.
