## Logging

Every Forma process (`forma serve`, `forma worker`, `forma start`, `forma migrate`) writes its log to stdout, one entry per line, so any log collector that reads container output picks it up. `forma authz` writes its log to stderr and its result to stdout.

### Log Levels

| Level | Used for |
| --- | --- |
| `debug` | Detail for debugging: rate-limit checks, smoke-test jobs. |
| `info` | Start-up, shutdown, migrations, one line per HTTP request, workflow reconciliation. |
| `warn` | Something that needs attention but did not fail: deprecated settings, an untrusted `X-Forwarded-For` chain. |
| `error` | A failed operation: a 5xx answer, a job that could not be delivered, a dependency that is unreachable. |
| `fatal` | Accepted for compatibility with forma2; nothing is logged at it. |
| `audit` | [Audit events](/self-hosting/advanced/enterprise-features/audit-logging), above every other level. |

`LOG_LEVEL` sets the minimum: `debug`, `info` (the default), `warn`, `error`, `fatal` (keeps only audit events) or `audit` (audit events only). Audit events pass every other level, so `LOG_LEVEL=error` still writes them. forma2 defaulted to `warn` in production; set `LOG_LEVEL=warn` for the same volume, at the cost of the start-up and request lines.

```env
LOG_LEVEL=info
```

### Log Format

`LOG_FORMAT=json` (the default) writes one JSON object per line; `LOG_FORMAT=text` writes `key=value` pairs for reading in a terminal. Every entry has:

- `time`: when it was written, RFC 3339 with microseconds and the zone, `Z` in a container running on UTC: `2026-10-23T09:14:02.481516Z`.
- `level`: `debug`, `info`, `warn`, `error` or `audit`, in lower case as forma2 wrote it.
- `msg`: the message.

and then the fields of the entry, such as `err`, `request_id`, `job_kind` or the audit event's fields. An HTTP request (other than `/health` and `/health/ready`) is logged as `http request` with `request_id`, `method`, `route` (the route pattern, never the raw path, which can carry a token), `status` and `duration` (nanoseconds in JSON).

```json
{
  "time": "2026-10-23T09:14:02.481516Z",
  "level": "info",
  "msg": "http request",
  "request_id": "0b3f6c2e-5d1a-4f7e-9c58-2a4e1d9b7f30",
  "method": "POST",
  "route": "/api/v2/client/:workspaceId/responses",
  "status": 200,
  "duration": 12873000
}
```

<Note>
  **Coming from forma2?** Its pino entries differed: `time` was milliseconds since the epoch (the Go server writes an RFC 3339 string), the message key was the same `msg`, and every entry carried `pid`, `hostname` and `name` (`"forma"`), which the Go server does not write; take the host from your collector's container metadata instead. The `level` labels are the same lowercase names, so a filter on `level` keeps working. forma2's `OTEL_LOGS_ENABLED` export of logs over OTLP has no counterpart: collect stdout.
</Note>

### Access Docker Container Logs

```bash
# One-click setup
cd forma
docker compose logs -f forma forma-worker

# Any container
docker logs -f <container-name>
```

### Access Kubernetes Pod Logs

```bash
kubectl logs -f deployment/forma -n <namespace>
kubectl logs -f deployment/forma-worker -n <namespace>
```

### Log Forwarding

Since every log goes to stdout, any collector works: Fluent Bit or Fluentd, Vector, the ELK stack, Datadog, Splunk, CloudWatch Logs, Grafana Loki.

## OpenTelemetry

The server and the worker export traces and metrics over OTLP HTTP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set. They are not Next.js processes: forma2's `OTEL_ENABLED`, `OTEL_ENDPOINT`, `NEXT_OTEL_VERBOSE` and `OTEL_LOGS_ENABLED` are not read.

```env
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_SERVICE_NAME=forma
# Optional: OTEL_EXPORTER_OTLP_HEADERS, OTEL_RESOURCE_ATTRIBUTES, OTEL_TRACES_SAMPLER, OTEL_TRACES_SAMPLER_ARG
```

`/v1/traces` and `/v1/metrics` are appended to the endpoint; only HTTP/protobuf is spoken. `deployment.environment` is `ENVIRONMENT`, else `NODE_ENV`, else `production`. Traces cover incoming HTTP requests, one span per request named by its `http.route` pattern; the `/health` liveness probe is not traced. Incoming W3C `traceparent` headers are honoured.

## Prometheus Integration

```env
PROMETHEUS_ENABLED=1
PROMETHEUS_EXPORTER_PORT=9464  # optional, 9464 by default
```

Each process then serves its metrics at `0.0.0.0:<port>/metrics`, a listener of its own beside the app's port. With Helm, a ServiceMonitor scrapes the server and the worker.

### Available Metrics

- **HTTP**: `http.server.request.duration` by `http.route`, method and `http.response.status_code` (`http_server_request_duration_seconds` in Prometheus).
- **Database pool**: `forma_db_pool_connections`, `forma_db_pool_max_connections`, `forma_db_pool_waits_total`, `forma_db_pool_wait_duration_seconds_total`.
- **Background jobs**: `forma_jobs_processed_total`, `forma_jobs_duration_seconds`, `forma_jobs_wait_duration_seconds` (the backlog signal), `forma_jobs_enqueue_total`; see [Job Runner](/self-hosting/configuration/job-runner).
- **Authorization**: the `forma_authzed_*` metrics in [AuthZed Operations](/self-hosting/advanced/authzed-operations#monitor-authzed).
- **Runtime**: the Go runtime and process collectors (`go_goroutines`, `go_memstats_*`, `process_cpu_seconds_total`, `process_resident_memory_bytes`, ...).

```yaml
scrape_configs:
  - job_name: "forma"
    static_configs:
      - targets: ["your-forma-host:9464"]
```

## Health Checks

```
GET /health        200 while the process serves HTTP; it touches no dependency (liveness)
GET /health/ready  200 when PostgreSQL answers (readiness)
```

Valkey and SpiceDB are deliberately not part of either: their outages degrade the features that need them without restarting or draining every replica. The image's `HEALTHCHECK` runs `forma healthcheck`, which probes `/health` on `HTTP_ADDR`.

## AuthZed and SpiceDB

The `forma_authzed_*` metrics cover authorization decisions (allow, deny, operational error) and their latency, outbox backlog, revocation delivery latency, the oldest pending item, dead letters, reconciliation drift and repairs. Revocation delivery warns at 15 seconds, becomes critical at 45 seconds, and makes protected operations fail closed at 60 seconds; a dead-lettered revocation reaches all three states at once. Also monitor SpiceDB's availability, datastore migrations, PostgreSQL pool saturation, dispatch latency and cache behaviour.

`/health` stays independent from SpiceDB. Check authorization with `forma authz schema check` and `forma authz outbox status` (see [AuthZed Operations](/self-hosting/advanced/authzed-operations), which also has metric names, PromQL examples, alert thresholds and the outage runbook).
