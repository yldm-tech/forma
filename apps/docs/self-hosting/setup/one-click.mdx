<Note>This only works with an Ubuntu machine, so ensure the underlying OS is verified beforehand!</Note>

If you're looking to quickly set up a production instance of Forma on an Ubuntu server, this guide is for you. `forma.sh` installs Docker if it is missing, writes the production [Docker Compose stack](/self-hosting/setup/docker) (the Forma server and its job worker, PostgreSQL 18, Valkey and SpiceDB) into `./forma`, puts Traefik in front of it with a Let's Encrypt certificate, and starts it.

<Note>
  **Traefik** is the reverse proxy: it routes incoming traffic to the containers and manages certificates through Let's Encrypt. The installer writes its service and labels into `forma/docker-compose.override.yml`, next to the release's unchanged `docker-compose.yml`.
</Note>

<Warning>
  The bundled RustFS option is designed for convenience on a single server. For high availability or larger production storage, use external object storage or a dedicated RustFS deployment. Keep `rustfs-data` on local SSD or NVMe storage rather than NFS or another network filesystem.
</Warning>

For other operating systems or a more customized installation, see the [Docker](/self-hosting/setup/docker) guide.

### Requirements

- An Ubuntu virtual machine with SSH access and `sudo`.
- A domain with an **A record** pointing to the server (and one for `files.<domain>` if you use the bundled object storage).
- Ports **80** and **443** open in the VM's security group, so Traefik can obtain a certificate.

### Deployment

Download the script from the `stable` branch, the release that `ghcr.io/yldm-tech/forma:latest` names, and run it:

```bash
curl -fsSL https://raw.githubusercontent.com/yldm-tech/forma/stable/deploy/docker/forma.sh -o forma.sh && chmod +x forma.sh && ./forma.sh install
```

The script downloads `docker-compose.yml` and its helper scripts from the same branch. To install a specific release, set `FORMA_REF=v0.2.<n>` (the release's tag) when running it, and pin the image with `FORMA_IMAGE_REF=ghcr.io/yldm-tech/forma:0.2.<n>` in `forma/.env`.

### Script Prompts

1. **Legacy Docker packages**: only when Docker is not installed yet, whether to remove `docker.io`, `containerd` and similar distribution packages that conflict with Docker CE.
2. **Domain**: the app domain, without `http://` or `https://`, for example `surveys.example.com`. It becomes `WEBAPP_URL`.
3. **HTTPS certificate**: whether Traefik should obtain a Let's Encrypt certificate. It asks to confirm that the domain points at the server with ports 80 and 443 open, then for the email address of the certificate. Answer no to set up TLS yourself (see [Custom SSL](/self-hosting/configuration/custom-ssl)).
4. **HSTS**: whether to redirect HTTP to HTTPS and send `Strict-Transport-Security`.
5. **Email**: whether to configure SMTP now (`MAIL_FROM`, `MAIL_FROM_NAME`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, authenticated SMTP, implicit TLS). Without it, email verification and password reset are switched off (`EMAIL_VERIFICATION_DISABLED=1`, `PASSWORD_RESET_DISABLED=1`), since nobody could receive the mail.
6. **File uploads**: whether to configure storage, then either an external S3-compatible service (access key, secret key, region, bucket, endpoint) or the bundled RustFS on a files subdomain (`files.<domain>` by default), whose administrator and least-privilege service credentials are generated.

The script then writes `forma/.env` (mode `0600`) with generated secrets, `ENCRYPTION_KEY`, `POSTGRES_PASSWORD`, `AUTHZED_TOKEN`, `AUTHZED_DATABASE_PASSWORD` and the RustFS credentials, plus your answers; writes `traefik.yaml`, `traefik-dynamic.yaml` and `docker-compose.override.yml`; pulls the images and runs `docker compose up -d`. Keep `forma/.env` private and include it in your backups: `ENCRYPTION_KEY` seals two-factor secrets, and losing it locks those users out.

Running `./forma.sh install` again in the same directory keeps the secrets already in `.env`.

When it finishes, open `https://<your domain>` and sign up: the instance admits its first user, who owns it, and afterwards only people with an invitation.

## Update

Run the update from the directory that contains the `forma/` folder, with the current script (replace an older `forma.sh`, in particular forma2's):

```bash
curl -fsSL https://raw.githubusercontent.com/yldm-tech/forma/stable/deploy/docker/forma.sh -o forma.sh
chmod +x forma.sh
./forma.sh update
```

The update:

1. Backs up `.env` (and, on a forma2 installation, `docker-compose.yml`) next to the originals with a timestamp suffix.
2. On a forma2 installation, moves the settings forma2's installer wrote into its compose file (`WEBAPP_URL`, the secrets, SMTP, storage) into `.env` and its Traefik service and labels into `docker-compose.override.yml`. See [forma2 to the Go server](/self-hosting/advanced/migration#forma2-to-the-go-server).
3. Updates `.env`: drops Prisma's `?schema=public` from `DATABASE_URL` and `MIGRATE_DATABASE_URL`, replaces `BULLMQ_WORKER_CONCURRENCY` x `BULLMQ_WORKER_COUNT` with `WORKER_CONCURRENCY`, maps the bundled RustFS credentials (`FORMA_RUSTFS_*`) to the storage profile, and comments out the [variables the Go server ignores](/self-hosting/configuration/environment-variables#variables-forma2-read-that-the-go-server-ignores).
4. Replaces `docker-compose.yml` and its helper scripts with the release's (a file that differed is kept as `<name>.<timestamp>`), validates the configuration, and restores the backups if it is invalid.
5. Pulls the images, checks the database (it refuses to start the Go server on a database that holds forma2's data but not yet its own; see the upgrade guide), and runs `docker compose up -d`: `forma-migrate` applies the migrations and `authzed-initialize` the authorization schema before the server and the worker restart.

Every step is idempotent, so running the update again is safe. Keep your own changes to the stack in `docker-compose.override.yml`; `docker-compose.yml` is replaced on every update.

For upgrades, restores, schema changes and relationship repair of SpiceDB, see [AuthZed Operations](/self-hosting/advanced/authzed-operations).

## Stop

```bash
./forma.sh stop
```

Runs `docker compose down` in `forma/`. The data volumes are kept.

## Restart

```bash
./forma.sh restart
```

## Cleanup RustFS init (optional)

```bash
./forma.sh cleanup-rustfs-init
```

Removes the finished `rustfs-init` container. It runs again, harmlessly, on the next `docker compose up`, since it is part of the storage profile. `./forma.sh cleanup-minio-init` is an alias.

## Uninstall

```bash
./forma.sh uninstall
```

After you type `yes`, it stops the stack and deletes `forma/` with its configuration and secrets. The Docker volumes (`forma_postgres`, `forma_redis`, `forma_rustfs-data`, ...) are kept; `docker volume rm` deletes them.

## Debug

```bash
./forma.sh logs
./forma.sh logs -f forma forma-worker
```

Arguments are passed to `docker compose logs`.

## Troubleshooting

- **Inbound rules**: ports 80 and 443 must be open in the VM's security group.
- **A record**: the domain (and the files subdomain) must point at the VM's IP address.
- **Containers**: `cd forma && docker compose ps -a` shows which service stopped; the one-shot `forma-migrate`, `authzed-db-bootstrap`, `spicedb-migrate` and `authzed-initialize` should have exited with code 0.
- **Logs**: `cd forma && docker compose logs forma forma-worker forma-migrate`. A server that exits at start-up names the variable it could not accept.
