## Overview

A self-hosted instance has no public sign-up. With email and password, it admits its first user, who owns the instance, and afterwards only people with an invitation from an organization owner or manager (or the roles `USER_MANAGEMENT_MINIMUM_ROLE` allows).

Single sign-on is different: whoever the identity provider lets through gets an account on their first sign-in, without an invitation, because the identity provider decides who may sign in. Configure only providers whose users should reach the instance.

## Where new SSO users land

| Variable | Effect |
| --- | --- |
| `AUTH_SSO_DEFAULT_ORGANIZATION_ID` | Every new SSO user joins this organization. It is created on the first such sign-up, whose user becomes its owner. An organization UUID, or the cuid2 id forma2 knew it by. |
| `AUTH_SSO_DEFAULT_ORGANIZATION_ROLE` | The role of the later SSO sign-ups in it: `owner`, `manager` (the default), `member` or `billing`. |

Without `AUTH_SSO_DEFAULT_ORGANIZATION_ID`, a new SSO user starts without an organization, as in forma2. A user following an invitation link joins the inviting organization either way.

```env
AUTH_SSO_DEFAULT_ORGANIZATION_ID=0197446e-5b20-7f31-a6c4-3e8d2b7f9a01
AUTH_SSO_DEFAULT_ORGANIZATION_ROLE=member
```

No licence is needed for any of this.

<Note>
  forma2's `AUTH_SKIP_INVITE_FOR_SSO` and `AUTH_SSO_DEFAULT_TEAM_ID` are not read. forma2 already let SSO users in without an invitation whatever the first said, and the second had no effect; to give new users access to workspaces, add them to a team after they join, or use the default organization above.
</Note>
