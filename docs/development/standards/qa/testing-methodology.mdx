## Overview

Test behaviour and outcomes at the cheapest level that can fail on them. A module ported from forma2 is done when forma2's tests for it are reproduced here and pass: those tests are the behaviour checklist. [AGENTS.md](https://github.com/yldm-tech/forma/blob/main/AGENTS.md) is the source of truth; this page explains how each level works.

| Level | Where | Runs with |
| --- | --- | --- |
| Go unit and integration tests | `*_test.go` next to the code in `server/` | `cd server && go test -race ./...` |
| TypeScript unit tests | `*.test.ts(x)` next to the code in each workspace | `pnpm test` (`vp run -r test`) |
| v3 API contract | `docs/api-v3-reference/contract-tests/` and `server/internal/app/v3_routes_test.go` | Schemathesis against a running server |
| Browser suite | `e2e/*.spec.ts` | `make e2e` (Playwright) against a running server |

## Go tests

1. **Location and shape**: tests live next to the code, in the same package, and are table-driven where several cases share one shape.
2. **Real dependencies**: a test that needs PostgreSQL, Valkey, SpiceDB or S3 starts the real thing with [testcontainers](https://golang.testcontainers.org/), never a mock of it:
   - `platform/pgtest` gives each test a fresh database cloned from a migrated template (`pgtest.GORM(t)`, `pgtest.DSN(t)`), so tests stay isolated without paying for a migration each.
   - `platform/valkey/valkeytest` gives a fresh Valkey database, `authz/spicedbtest` a SpiceDB, `storage/s3test` an S3 bucket.
   - `mailer/mailertest.Transport` captures sent mail.
   - `v3api/v3apitest` mounts a feature module's handlers with the production middleware around a real database, authorization and API keys.
   - `go test -short` skips everything that needs Docker.
3. **Determinism**: CI runs the suite under the race detector on four-core runners. Wait on observable conditions rather than on time, never depend on real time staying inside a window or TTL, and seed a counter instead of looping requests up to a rate limit.
4. **Coverage**: measured, not targeted, with one gate: `server/internal/auth`, `server/internal/authz` and `server/internal/apikey` must stay at 80% statement coverage or above (the `Go coverage` job in `pr.yml`), as forma2 held its authentication and authorization code.

```bash
cd server
go test ./internal/health -run TestReady     # one test
go test -race ./internal/seed/...             # one package, as CI runs it
go test -short ./...                          # everything that needs no Docker
```

## TypeScript tests

1. **Vitest, through Vite+**: tests import from `vite-plus/test` and sit next to the file they test (`utils.test.ts` tests `utils.ts`).
2. **Organization**:

   ```typescript
   import { describe, expect, test } from "vite-plus/test";

   describe("ComponentName or FeatureName", () => {
     describe("functionName or scenario", () => {
       test("describes the expected behaviour", () => {
         // test implementation
       });
     });
   });
   ```

3. **Mocking**: mock what crosses the boundary of the unit (the network, timers, a sibling module's side effects), never the unit itself.
4. **Builds first**: packages are consumed through their builds, so run `pnpm build` before believing a failure in a file you never touched after a branch switch.
5. **Every test runs somewhere**: `pnpm tests:run-check` (`scripts/check-tests-run.mjs`) fails when a committed test file sits outside every workspace with a `test` script, where nothing would ever run it. The Playwright specs under `e2e/` are the one exception.

```bash
pnpm exec vp run --filter @forma/surveys test -- src/lib/logic.test.ts   # one file
pnpm test                                                               # every workspace, after a build
```

## The v3 API contract

- `TestV3RouteParity` builds the production router and fails when an `/api/v3` operation is served but not documented in `docs/api-v3-reference/openapi.yml`, or documented but not served.
- The `API v3 Contract Tests` workflow seeds a server (`forma seed --contract`) and runs [Schemathesis](https://schemathesis.readthedocs.io/) against the bundle: every documented operation, with seeded identifiers, checked for its status codes, content type and response schema. [The contract-tests README](https://github.com/yldm-tech/forma/blob/main/docs/api-v3-reference/contract-tests/README.md) has the local invocation.

## The browser suite

[Playwright](https://playwright.dev/) specs live in `e2e/` (configuration in `playwright.config.ts`) and drive a running server: sign-up and onboarding, a link survey published, answered on its public page and its response filtered and exported, an app survey shown by the SDK on a host page, an image uploaded in the survey editor, and [axe](https://github.com/dequelabs/axe-core) WCAG 2.2 AA checks on the login page, the survey editor and a public survey page at a desktop and a phone viewport. Every spec creates the account it works in, so specs run in parallel against one instance.

```bash
make build                          # the SPA and SDK bundles embedded in bin/forma
bash scripts/ci-stack.sh up         # dependencies in Docker, then `forma start` on :3000
pnpm exec playwright install chromium
make e2e                            # or: pnpm exec playwright test e2e/link-survey.spec.ts
bash scripts/ci-stack.sh down
```

The `E2E Tests` workflow runs the suite on pull requests that change the UI, the survey runtime or the SDK. It is not a required check.

What earns a spec:

1. **Level**: prove a behaviour at the cheapest level that can fail on it. A feature's happy path or a journey across several surfaces is a browser spec; business logic, invariants and anything pure is a unit test; a route's authorization, response shape or query scoping is a Go test on that route.
2. **Unit of coverage**: one spec per feature area, not per ticket and not per component. Inside an area that already has a spec, journey behaviour extends it, logic goes to a unit test, and UI detail is verified manually and recorded in the PR.
3. **Cost**: every spec is paid on every run, and the suite can never be faster than its slowest test.

## Development data

`make seed` (`forma seed`, which refuses to run without `ALLOW_SEED=1`) writes forma2's demo data: an organization with an owner, a manager and a member (`admin@forma.ylam.ai`, `manager@forma.ylam.ai`, `member@forma.ylam.ai`, all with the password `Password#123`), a workspace with four surveys, one of them carrying every element type, 150 responses and demo workflows with run history. Seeding again rewrites the same rows; `make seed-clear` removes what the seed wrote and seeds again. With `SEED_API_KEY` set it also creates an API key, `fbk_<SEED_API_KEY>`, with manage access to the seeded workspace.

## Other checks on every pull request

- **Translations**: `pnpm scan-translations` checks the admin UI's and the survey runtime's catalogues against the code that reads them, the Go mailer and survey template catalogue included.
- **Bundle budgets**: `pnpm bundle:check` fails when the gzipped `surveys.umd.cjs` or `forma.umd.cjs`, which every respondent downloads, outgrows its budget in `scripts/check-bundle-budget.mjs`.
- **Migrations**: new and changed goose migrations are linted with Squawk (`scripts/lint-migrations.sh`).
