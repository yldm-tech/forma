#### Custom Configurations

Every Forma process (`forma serve`, `forma worker`, `forma start`, `forma migrate` and `forma authz`) reads its configuration from the environment once, when it starts. With Docker Compose and the one-click install the settings live in `.env` next to `docker-compose.yml`; with Helm, in the chart's values and Secrets. Restart the containers after changing a value.

A missing required variable or a malformed value stops the process at start-up with a message that names the variable, rather than starting with a guess. Switches are forma2's `1` or `0`; any other spelling fails the start. The exceptions keep forma2's wider spellings: `AUTHZED_ENABLED` and `AUTHZED_INSECURE` also take `true` and `false`, and `SKIP_STARTUP_MIGRATION` takes `true` and `false`.

<Note>
  Moving from forma2 to the Go server? Read the [upgrade guide](/self-hosting/advanced/migration#forma2-to-the-go-server) first. The variables forma2 read that the Go server ignores are listed [below](#variables-forma2-read-that-the-go-server-ignores); `./forma.sh update` comments them out of `.env`.
</Note>

For the `AI_*` variables, see [AI Features](/self-hosting/advanced/enterprise-features/ai-features): it walks through each provider and the credentials it needs. Set only the variables of the provider you use.

#### Server and database

| --- | --- | --- | --- |
| WEBAPP_URL | Base URL of the admin app, for example `https://forma.example.com`. OAuth and MCP URLs are derived from it. | required | |
| PUBLIC_URL | Separate origin for public surveys and the client API. OAuth and MCP do not use it. | optional | WEBAPP_URL |
| HTTP_ADDR | Listen address of `forma serve`. | optional | `:3000` |
| SHUTDOWN_TIMEOUT | How long in-flight requests, and in the worker running jobs, get to finish after SIGTERM, as a Go duration (`20s`, `1m`). | optional | `20s` |
| DATABASE_URL | PostgreSQL 18 (or newer) connection URL. forma2's Prisma suffix `?schema=public` is accepted and dropped; any other `schema` value fails the start, since the server keeps its tables in the `public` schema. | required | |
| MIGRATE_DATABASE_URL | Used instead of `DATABASE_URL` by `forma migrate` (and the migration step of `forma start`, `forma wait-for-database`): a role allowed to change the schema while the processes connect with a narrower one. Same `?schema=public` rule. | optional | DATABASE_URL |
| DATABASE_MAX_OPEN_CONNS | Connection pool size of one process; every process has its own pool. | optional | 20 |
| SKIP_STARTUP_MIGRATION | `true` makes `forma start` skip its migrations, for deployments where a separate `forma migrate` job applies them (Helm, Docker Compose). | optional | false |
| REDIS_URL | Valkey (or Redis) for rate-limit counters and short-lived state. Every process needs it; while it is unreachable, rate limits let requests through. It no longer holds a job queue. | required | |
| ENCRYPTION_KEY | Seals secrets stored at rest (two-factor secrets and backup codes) and signs single-use and personal links. 64 hex characters (`openssl rand -hex 32`) or exactly 32 characters; an instance moved from forma2 must keep its value. | required | |
| ENCRYPTION_KEY_VERSION | Version written in front of every value `ENCRYPTION_KEY` seals, 1 to 255. Give a new key a new version when rotating. | optional | 1 |
| ENCRYPTION_PREVIOUS_KEYS | Retired keys still accepted to open what they sealed, as `<version>:<key>,...`. A 32-character key that contains a comma must be given in hex. | optional | |
| NEXTAUTH_SECRET | forma2's signing secret. Kept so that the link survey email verification and PIN tokens forma2 issued keep verifying; at least 32 characters. Without it these tokens are signed with a secret derived from `ENCRYPTION_KEY`. | optional | |
| BETTER_AUTH_SECRET | forma2's Better Auth secret, used before `NEXTAUTH_SECRET` for link survey PIN tokens; at least 32 characters. | optional | NEXTAUTH_SECRET |
| TRUSTED_PROXY_HOP_COUNT | How many reverse proxies in front of the server append to `X-Forwarded-For`; the client address is the entry that many places from the right. `0` means none: the TCP peer is the client. | RATE_LIMITING_DISABLED | `1` turns the server's own rate limits off. It does not disable a gateway in front of it. | optional | 0 |
| GATEWAY_RATE_LIMITING | `1` declares a gateway (Envoy or equivalent) in front of the server that enforces forma2's rate-limit policy: the client API routes it covers (response, display, environment, user and upload requests) and requests to `/api/v1/management/*` and `/api/v1/webhooks/<id>` that send their API key in `x-api-key` are then not limited again by the server. Leave it unset with Docker Compose, which runs no gateway. | optional | 0 |
| WORKER_CONCURRENCY | Jobs one `forma worker` process runs at once; `0` derives it from the CPU count (2 to 4). See [Job Runner](/self-hosting/configuration/job-runner). | optional | 0 |
| BULLMQ_WORKER_CONCURRENCY, BULLMQ_WORKER_COUNT | forma2's worker settings, still honoured when `WORKER_CONCURRENCY` is unset: the worker runs `BULLMQ_WORKER_COUNT x BULLMQ_WORKER_CONCURRENCY` jobs at once and logs a deprecation warning. Ignored, with a warning, when `WORKER_CONCURRENCY` is set. | optional | |
| BULLMQ_WORKER_ENABLED | Read by `forma start` only: `0` serves without the in-process job worker, for deployments that run `forma worker` separately. | optional | 1 |
| SURVEY_SCHEDULING_TIME_ZONE | IANA time zone in which scheduled surveys are published and closed. | optional | Europe/Berlin |
| SURVEY_SCHEDULING_LOCAL_HOUR, SURVEY_SCHEDULING_LOCAL_MINUTE | The local time of day, in that zone, at which a publish or close date takes effect. | optional | 0, 0 |
| LOG_LEVEL | `debug`, `info`, `warn`, `error`, `fatal` (only what is above error, which is audit events) or `audit` (audit events only). forma2 defaulted to `warn` in production; the Go server defaults to `info`, the level it logs its start-up and shutdown at. Any other value fails the start. | optional | info |
| LOG_FORMAT | `json` (one object per line, for log pipelines) or `text`. See [Monitoring](/self-hosting/setup/monitoring). | optional | json |
| HTTP_PROXY, HTTPS_PROXY, NO_PROXY | Go's standard proxy variables, honoured by outbound HTTP requests. Webhook deliveries never use them: they connect directly to the address they validated. | optional | |
| SSL_CERT_FILE, SSL_CERT_DIR | Trust a private certificate authority (an SMTP server or S3 endpoint with an internal CA): Go's standard locations for extra root certificates, in place of forma2's `NODE_EXTRA_CA_CERTS`. | optional | |

#### Sign-up, sign-in and users

| Variable | Description | Required | Default |
| --- | --- | --- | --- |
| EMAIL_AUTH_DISABLED | `1` switches email and password sign-up and sign-in off, for SSO-only instances. | optional | 0 |

| PASSWORD_RESET_DISABLED | `1` refuses every password reset. Needed without SMTP. | optional | 0 |
| PASSWORD_RESET_TOKEN_LIFETIME_MINUTES | How long a reset link stays valid, 5 to 120 minutes. | optional | 30 |
| PASSWORD_HIBP_CHECK_DISABLED | `1` skips the Have I Been Pwned breach check when a password is set, for deployments without egress. The check fails open on network errors. | optional | 0 |
| INVITE_DISABLED | `1` switches inviting members off. Pending invites can still be accepted. | optional | 0 |
| INVITE_RATE_LIMIT_PER_24_HOURS | Invite recipients one organization may be sent per day. | optional | 50 |
| SESSION_MAX_AGE | Session lifetime in seconds. | optional | 86400 |
| USER_MANAGEMENT_MINIMUM_ROLE | Lowest organization role allowed to manage members and invites: `owner`, `manager` or `disabled`. | optional | manager |
| TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY | Cloudflare Turnstile on sign-up, when both are set. | optional | |
| RECAPTCHA_SITE_KEY, RECAPTCHA_SECRET_KEY | Google reCAPTCHA v3; surveys can turn on spam protection only when both are set. | optional | |

A self-hosted instance admits its first user and invitees only; there is no open sign-up outside Forma Cloud (`IS_FORMA_CLOUD=1`) and end-to-end test runs (`E2E_TESTING=1`), whatever the build. forma2's development builds opened sign-up; the Go server has no development mode. Single sign-on is the exception: whoever a configured identity provider admits gets an account on their first sign-in (see [Authentication Behavior](/self-hosting/auth-behavior)).

#### Variables forma2 read that the Go server ignores

They do no harm if left in place, but nothing reads them; `./forma.sh update` comments them out of `.env`.

| Variable | Why |
| --- | --- |
| CRON_SECRET | Periodic work runs inside `forma worker`; no endpoint is called from outside. |
| BULLMQ_EXTERNAL_WORKER_ENABLED | The job queue is River on PostgreSQL. `BULLMQ_WORKER_ENABLED`, `BULLMQ_WORKER_CONCURRENCY` and `BULLMQ_WORKER_COUNT` are still read, as described above. |
| AUTHZED_SYSTEM_KEY | The SpiceDB object namespace is fixed by the schema. |
| FORMA_AUTHZED_V6_MIGRATION_ACKNOWLEDGED | forma2's installer gate; `forma.sh update` now checks the installation itself. |
| AUTH_SKIP_INVITE_FOR_SSO, AUTH_SSO_DEFAULT_TEAM_ID | Dead in forma2 already: every SSO sign-up gets an account without an invite and joins `AUTH_SSO_DEFAULT_ORGANIZATION_ID` when it is set. |
| OIDC_SIGNING_ALGORITHM | The provider's discovery document says how its tokens are signed. |
| ENTERPRISE_LICENSE_KEY | Every feature is available without a licence. |
| DEBUG, DEBUG_SHOW_RESET_LINK | The Go mailer has no SMTP debug output and there is no development build. |
| ASSET_PREFIX_URL, DEFAULT_BRAND_COLOR, SENTRY_AUTH_TOKEN | Build-time settings of forma2's Next.js app. |
| OTEL_LOGS_ENABLED | Logs are not exported over OTLP; collect them from stdout (see [Monitoring](/self-hosting/setup/monitoring)). |
| NODE_EXTRA_CA_CERTS | Use `SSL_CERT_FILE` or `SSL_CERT_DIR`. |

#### OAuth and MCP URLs

The MCP server is available on the admin app at `/api/mcp`. OAuth discovery and token issuance are also admin app surfaces:

```text
{WEBAPP_URL}/api/mcp
{WEBAPP_URL}/.well-known/oauth-protected-resource/api/mcp
{WEBAPP_URL}/.well-known/oauth-authorization-server/api/auth
```

Do not point MCP or OAuth clients at `PUBLIC_URL`; that origin is reserved for public survey delivery and SDK traffic.

#### AuthZed / SpiceDB Authorization

SpiceDB is the only authorization evaluator. While it is disabled every permission check fails closed, so an instance needs it configured.

| Variable | Description | Required when enabled | Default |
| --- | --- | --- | --- |
| AUTHZED_ENABLED | Turns the SpiceDB client on. `1`/`0` or `true`/`false`. | required | `0` (Docker Compose and Helm set `1`) |
| AUTHZED_ENDPOINT | SpiceDB's gRPC address as `host:port`, without a scheme or path. | required | `spicedb:50051` in Docker Compose |
| AUTHZED_TOKEN | gRPC preshared key. Load it from a secret. | required | |
| AUTHZED_INSECURE | Plaintext gRPC instead of TLS, for an in-cluster service. `1`/`0` or `true`/`false`. | optional | `0` (Docker Compose and Helm set `1` for the bundled SpiceDB) |
| AUTHZED_CONSISTENCY | `fully_consistent` evaluates every check at the newest revision; `minimize_latency` lets SpiceDB answer from its cache, so a delivered revocation can take effect a few seconds later. | optional | fully_consistent |

Docker Compose additionally needs `AUTHZED_DATABASE_PASSWORD` for SpiceDB's own PostgreSQL login; generate it and `AUTHZED_TOKEN` with `openssl rand -hex 32`. `SPICEDB_IMAGE_REF` overrides the bundled `authzed/spicedb:v1.52.0` image.

An endpoint must be a bare `host:port` with a port from 1 to 65535, for example `spicedb:50051`, `grpc.authzed.com:443` or `[::1]:50051`. Supplied values are validated even while SpiceDB is disabled, and the token is never printed.

Check the connection and the schema without changing anything:

```bash
# Docker Compose
docker compose --profile authzed-ops run --rm authzed-ops schema check
# Kubernetes (the image has no shell; run the binary directly)
kubectl -n forma exec deploy/forma -- forma authz schema check
```

The command prints one JSON object and exits `0` when SpiceDB holds the schema the release ships, `2` on drift and `1` on failure. `forma authz backfill`, `forma authz outbox status|drain|replay` and `forma authz schema apply` complete the set; see [AuthZed Operations](/self-hosting/advanced/authzed-operations). SpiceDB is not part of `/health`, readiness or start-up, so a SpiceDB outage fails the operations that need a permission check without restarting Forma.
