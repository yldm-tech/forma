---
title: "Custom Subpath"
description: "Serving Forma under a URL prefix is not supported by the Go server."
icon: "link"
---

<Warning>
  The Go server does not support a custom subpath. It serves the admin app, the survey pages, the APIs, OAuth and MCP from the root of its origin (`/`, `/s/...`, `/api/...`, `/.well-known/...`), and there is no `BASE_PATH` setting: forma2's build-time `BASE_PATH`, a Next.js base path, has no counterpart, and building your own image with it has no effect.
</Warning>

### What to do instead

Give Forma a hostname of its own, for example `https://forma.example.com` or `https://feedback.example.com`, and point your reverse proxy or DNS at it. `WEBAPP_URL` is that origin, without a path:

```bash
WEBAPP_URL=https://forma.example.com
```

To keep the public surveys and the SDK on a separate hostname, set `PUBLIC_URL` as described in [Domain Configuration](/self-hosting/configuration/domain-configuration).

### Moving a forma2 subpath deployment

A forma2 instance served under a prefix (`https://example.com/custom-path`) moves to its own hostname before switching to the Go server:

1. Set up the new hostname, its certificate and the proxy route to port 3000.
2. Set `WEBAPP_URL` to the new origin, and remove the prefix from `NEXTAUTH_URL` and `BETTER_AUTH_URL` (or remove both: they default to `WEBAPP_URL`).
3. Register the callback URLs on the new origin with your single sign-on providers and integrations: the same paths as before, without the prefix (see [Single sign-on](/self-hosting/configuration/auth-sso/open-id-connect) for each provider's). Update MCP clients to `https://forma.example.com/api/mcp`.
4. Keep the old prefix redirecting to the new hostname for a while, so that survey links and SDK snippets already shared keep working; an SDK snippet with the old `appUrl` should be updated.

Object storage is unaffected: keep the S3 API at the root of its own endpoint (`S3_ENDPOINT_URL`), as before. See [File Uploads Configuration](/self-hosting/configuration/file-uploads).
